# Code boundaries

Where code may be shared, and where it deliberately is not (#1731). Reuse and extraction happen **inside** a boundary. Crossing one is a design decision: propose it in the PR, never do it to save a few lines. `/reuse-check` (`.claude/skills/reuse-check/SKILL.md`) and the clone ratchet (`scripts/check-clones.mjs`, one scan per boundary below) both read this page.

Everything here is derived from config, cited by file. If config and this page disagree, config wins: fix the page.

## The boundaries

| Boundary | What it is | Where shared code goes inside it | Clone scan (`scripts/clones.json`) |
|---|---|---|---|
| `frontend/` | Desktop renderer (React, Vite) | `frontend/src/components/ui/` (primitives; CLAUDE.md requires them), `frontend/src/hooks/`, `frontend/src/utils/`, `frontend/src/services/` | `frontend` |
| `mobile/` | Mobile app (Expo / React Native), its own pnpm project | `mobile/components/ui.tsx` (primitives), `mobile/components/`, `mobile/hooks/`, `mobile/lib/` | `mobile` |
| Rust workspace | Every crate in root `Cargo.toml` `[workspace] members` | The lowest crate that **already** sits under every user (see the graph) | `rust` |
| `website/` | Static pages on Cloudflare Pages, no build step | A shared `.js` / `.css` file that each page includes with `<script src>` / `<link>` | `website` |

Not scanned, each for a reason: `e2e/` (test code), `pollis-delivery/worker/` (one small TypeScript Worker, its own tsconfig), `learn/manim/` (Python video sources), `scripts/` (one-off tools), `fuzz/` (detached from the workspace on purpose), `patches/` (vendored upstream stand-ins).

## frontend/ and mobile/: share features, not code

- **Separate pnpm projects.** `pnpm-workspace.yaml` lists `frontend`, `e2e` and `pollis-delivery` only. `mobile/` has its own `package.json` and `pnpm-lock.yaml`, so every `pnpm` call there needs `--ignore-workspace`. The two never share `node_modules` and cannot import each other's packages.
- **No imports across.** `mobile/` never imports from `frontend/`, and `frontend/` never imports from `mobile/`. React DOM and React Native components are not interchangeable anyway.
- **The sanctioned shared channels:**
  1. **Locale catalogues.** `mobile/metro.config.js` adds exactly one watch folder, `../frontend/src/i18n/locales`; `mobile/i18n/resources.ts` (generated by `scripts/mobile-i18n-resources.mjs`) imports the JSON from there. Nothing else in `frontend/` is watched, so any other import would fail to bundle.
  2. **`pollis-core` through uniffi.** `mobile/modules/pollis-native/ubrn.config.yaml` builds `../../../pollis-core` (`--no-default-features`, no desktop media stack). Desktop reaches the same code through the Tauri shims in `src-tauri/`. Logic both apps need belongs here (CLAUDE.md "Perf & media are Rust-first").
  3. **Wire types in `pollis-api`**, reached by both apps only through `pollis-core`.
- **Parity twins, kept on purpose.** Small pure modules are copied, and a mobile test holds the copy to desktop's file. Edit both together; never "deduplicate" them with an import:

  | Mobile copy | Desktop original | Held by |
  |---|---|---|
  | `mobile/lib/drafts.ts` | `frontend/src/utils/drafts.ts` | `mobile/tests/drafts.test.ts` |
  | `mobile/lib/links.ts` | `frontend/src/utils/links.ts` | `mobile/tests/links.test.ts` (byte-identical) |
  | `mobile/lib/username.ts` | `frontend/src/utils/username.ts` | `mobile/tests/username.test.ts` |
  | `mobile/lib/identityFields.ts` | `frontend/src/utils/identityFields.ts` | `mobile/tests/identity-fields.test.ts` |
  | `mobile/lib/securityEvents.ts` | `frontend/src/components/Security/securityEvents.ts` | `mobile/tests/security-events.test.ts` |
  | `mobile/lib/dmActivity.ts` | `frontend/src/utils/dmActivity.ts` | `mobile/tests/dm-activity.test.ts` (byte-identical) |
  | `mobile/i18n/languages.ts`, `namespaces.ts` | `frontend/src/i18n/languages.ts`, `namespaces.ts` | `mobile/tests/i18n.test.ts` |
  | `mobile/types/index.ts` | `frontend/src/types/index.ts` (and the Rust structs) | by hand |

  UI twins (a screen per platform, e.g. `mobile/components/self/SecurityEventRow.tsx` ↔ `frontend/src/components/Security/SecurityEventRow.tsx`) are cross-referenced in `ui.md`. They are parity pairs, not duplication.
- **When logic genuinely must be shared,** the answer is usually Rust in `pollis-core`, exposed as a command to both apps. A new shared TypeScript channel (another metro watch folder, a shared package) is a design change: propose it in the PR.

## The Rust crate graph

Path dependencies from each crate's `Cargo.toml` (`dev` = dev-dependency only):

```
src-tauri (pollis)      → pollis-core, pollis-capture-proto        dev: pollis-api, pollis-delivery, pollis-sqlcipher
pollis-tui              → pollis-core                               dev: pollis-api, pollis-delivery
pollis-core             → pollis-api, pollis-schema, pollis-device-cert, pollis-relay,
                          verifiable-log-serve, pollis-capture-proto, pollis-sqlcipher
pollis-delivery (DS)    → pollis-api, pollis-schema, pollis-device-cert, pollis-libsql-connector
pollis-relay            → pollis-device-cert, verifiable-log
verifiable-log-serve    → verifiable-log, verifiable-log-builder    dev: pollis-relay
verifiable-log-builder  → verifiable-log, pollis-libsql-connector (optional)
pollis-capture-linux/-macos → pollis-capture-proto
leaves: pollis-api, pollis-schema, pollis-device-cert, verifiable-log, pollis-capture-proto,
        pollis-sqlcipher, pollis-libsql-connector, patches/device-info
```

Rules that follow from it:

- **The client and the DS share only through `pollis-api` (wire types), `pollis-schema` (migrations) and `pollis-device-cert`.** `pollis-core` never depends on `pollis-delivery`, and the DS never on `pollis-core`. A helper both need moves to one of those shared leaves, or stays duplicated.
- **`pollis-core` does not depend on `libsql`** (#987; the client holds no database credential). Only `pollis-delivery` and `verifiable-log-builder` reach libsql, both through `pollis-libsql-connector` (#1303).
- **Never add a dependency edge just to reuse a helper.** Move the helper to a crate both sides already depend on, or leave the copy and say why in the PR. Example: `constant_time_eq`, once copied five times across `pollis-core` and `pollis-delivery`, lives in `pollis-device-cert`, a leaf both already depend on (#1731).
- `src-tauri` is a thin shim layer: logic lives in `pollis-core` (CLAUDE.md "Command path"), so a helper in `src-tauri` that `pollis-core` also needs belongs in `pollis-core`.
- The capture helpers are separate processes; they share only `pollis-capture-proto`.
- `fuzz/` and `patches/openmls-sqlite-storage`, `patches/sqlcipher-src` are excluded from the workspace (`Cargo.toml` `exclude`).

## website/

- Static HTML, CSS and JavaScript uploaded as-is (`.github/workflows/website-deploy.yml` runs `wrangler pages deploy website`, no build step). There is no bundler and no template engine.
- **Reuse means a shared file each page includes:** `styles.css` and `doc-page.css` for styles, `script.js` (the site-wide script), `copy.js` (every copy-to-clipboard button: `data-copy` / `data-copy-from`, tested by `scripts/test-website-copy.mjs`). Page-specific logic stays in the page's own file (`artifacts.js`, `transparency.js`, `assurance.js`, `learn.js`, `verify-downloads.js`).
- **Page chrome is repeated by design.** The `<head>`, nav and footer appear in every page because there is no include mechanism. That repetition is in the clone baseline; do not inject chrome with JavaScript to remove it (it would make the pages depend on scripts to render their own navigation).
- `website/artifacts.js` also carries the pinned transparency-log key, one of the copies `scripts/check-pinned-log-key.py` holds equal to `pollis-core`'s constant. Those copies are deliberate (each audience reads its own), not duplication.
