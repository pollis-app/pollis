# Drift sweeps

Checks that keep what we publish true to what the code does (epic #1720). Each sweep owns its own data file in `scripts/` or its test; this article has one section per sweep. **None of them run in CI or gate a merge:** they are one-off checks run by hand before a release that affects every app, via `/pre-release-sweeps` (`.claude/skills/pre-release-sweeps/SKILL.md`).

## CLI invocations (#1721)

- **Parse check:** `verifiable-log-serve/tests/doc_invocations.rs` extracts every `pollis-verify …` command from tracked docs, website pages, `/learn`, READMEs and workflows, and parses each with the shipped clap definition (`verifiable_log_serve::cli`). Only code counts as a command: fenced blocks and inline code in Markdown, `<code>`/`<pre>` in HTML (and HTML inside JS strings), and whole script/workflow files; prose naming the tool is skipped. `<placeholders>`, `$VARS`, `{x}` and `vX.Y.Z` parse as dummies. A subcommand named alone (or with only its flags, `release --json`) is a reference and only has to exist. Its three doc-reading tests are `#[ignore]`d so no Rust CI run trips on a doc edit; the sweep runs them with `cargo test -p verifiable-log-serve --test doc_invocations -- --include-ignored`.
- **Reverse check:** every subcommand and every long flag, plus `--version`, must appear in a public doc (`website/`, `docs/verify-transparency-log.md`, `docs/transparency.md`, `README.md`). A new subcommand or flag without docs fails.
- **Live check:** commands with no placeholders that target `https://verify.pollis.com` are listed in `verifiable-log-serve/tests/doc_invocations.live.txt` (the test fails if the list is stale; regenerate with `UPDATE_DOC_INVOCATIONS=1 cargo test -p verifiable-log-serve --test doc_invocations`). The sweep downloads the latest `pollis-verify-v*` release, checks its `.sha256`, and runs each one against the live log; any non-zero exit fails.
- **`pollis` (the terminal client):** not covered. It has no clap definition and no subcommands, only `--help` and `--version` (`pollis-tui/src/cli.rs`, whose own tests pin the help text), so there is no invocation surface to drift.
- **Installers:** `scripts/check-install-env.py` checks that every `POLLIS_*` variable `website/install.sh` / `cli-install.sh` reads is documented (today in `docs/deployments.md`), and that no doc shows one with an installer that ignores it.

## Facts (#1722)

- **Registry:** `scripts/facts.json` declares every public number or policy value once: `value_from` (the constant, wrangler var, migration, infra default or CLAUDE.md line that makes it true; several sources must agree, e.g. a DS code default and `wrangler.prod.jsonc`) and `asserted_in` (every page or doc that states it). Patterns use `{value}`, which matches the value as digits, with thousands separators, or as a word (`12` / `twelve` / `Twelve`; `words: false` turns words off). Text is matched with HTML tags and entities removed, Markdown `**` removed and whitespace collapsed, so rewrapping or adding `<strong>` does not unanchor a fact.
- **Checker:** `scripts/check-facts.mjs`, run by the sweep. It fails when a copy states a different value, when a pattern is not found at all (reworded or moved copy: re-anchor it in the same PR), when `value_from` extracts nothing, when two sources disagree, and on an empty registry. Failures print `file:line` and a fix hint.
- **Deployed:** after the release's website deploy, the sweep runs `check-facts.mjs --deployed https://pollis.com`, checking every `website/**` assertion against the live page (`/learn.html` → `/learn`, fetched with redirects). It replaced `website-verify.yml`'s bespoke "accepted-loss count on /learn" step. Red here and green in the repo means the site lags `main`: deploy it.
- **Disputed:** `status: "disputed"` (on a fact or one assertion, with a `note`) turns its problems into warnings that print both values. Reserved for legal/policy pages (`privacy`, `terms`, `subprocessors`, `legal-requests`, `docs/metadata-retention-policy.md`) that disagree with code: neither side is automatically right, so the owner decides (epic #1720). A disputed fact that agrees again warns until the status is cleared.
- **Self-test:** `scripts/test-check-facts.sh` copies every file the registry reads (`check-facts.mjs --list-files`) into a temp tree and proves a code change, a copy change, a reworded copy, a renamed constant, disagreeing sources, and an empty registry each fail, and that a disputed fact only warns.
- **Adding a fact:** add it to `facts.json` with every copy you can find (`grep` the number and its word form across `website/`, `learn/`, `docs/`, `README.md`, `CLAUDE.md`), and run `node scripts/check-facts.mjs`.
- **Not covered:** numbers that are history, not policy (leaf counts on a given date, past review dates), arithmetic in prose (log₂ of a group size), third-party limits (store character caps, Play's tester rules), and claims with no code or config behind them (the transparency-report cadence, the disclosure window in `SECURITY.md`). Judgment claims belong to the claims audit (#1723).

## Claims (#1723)

- **Ledger:** `scripts/claims.json` records every falsifiable claim the public material makes about how Pollis works (the docs in its `audited_docs`: the `/learn` scripts and page, the security whitepaper, `security-explained`/`-simple`, the verify, transparency, reproducibility and continuity docs, the store copy, and every public `website/` page). Each claim has the exact sentence (`locator.quote` in `doc`), a normalised `claim`, a `kind` (`security|behaviour|process|number|cli`), `anchors` (the paths or globs whose change could make it false), `evidence` (the `path:line` it was checked against), an optional `fact` (the `facts.json` id for a number), a `status` (`verified|unverifiable|disputed`, with a `note` for the last two) and `verified_sha`. The baseline audit was #1723.
- **Validator:** `node scripts/check-claims.mjs`, run by hand by `/sweep-claims` and before a release. It is a sweep check, so it is **not in CI and never gates a merge**. It fails on:
  - a schema error, an unknown `fact`, an audited doc with no claims, or an empty ledger;
  - an anchor path or glob that matches no file (the code was deleted or moved: re-anchor and re-verify);
  - a `locator.quote` that no longer appears in its doc (the copy was reworded: re-verify).

  Quotes are matched on the same normalised text as `check-facts.mjs` (`scripts/lib/doc-text.mjs`). Disputed claims (policy pages that disagree with code, #1720) print as warnings.
- **Impact:** `node scripts/claims-impact.mjs --since <ref>` (or `--ledger`) lists the claims whose anchors changed in `git diff <ref>..HEAD`, grouped by doc. `--summary` gives the one line `scripts/release-impact.sh` prints, per PR and (in the full report) since the last claims sweep.
- **Sweep:** `/sweep-claims` (`.claude/skills/sweep-claims/SKILL.md`) re-verifies only the due claims with the audit rubric, fixes them, then bumps `verified_sha` and `scripts/sweep-ledger.json` → `claims`.
- **/learn copies:** the narration script `learn/manim/scripts/<slug>.md` is the source of truth for a topic's words. `scripts/check-learn-sync.mjs` (by hand, with the validator) fails when a caption cue or an on-page transcript paragraph differs from its script beat. The caption track is `website/learn/media/<slug>.vtt`, now kept in git and served from pollis.com. `--write` regenerates the captions and the transcript from the scripts. The #1723 audit found all three copies had drifted apart since July. The videos themselves stay on `cdn.pollis.com`.
- **Self-test:** `scripts/test-check-claims.sh` copies what the ledger reads into a temp tree. It proves that each of these fails:
  - a deleted anchor file, or a glob anchor with every match deleted;
  - a reworded quote;
  - an unknown fact or kind, or a duplicate id;
  - an empty ledger, or an orphaned audited doc.

  It also proves that `/learn` drift fails and that `--write` repairs it. Run it locally after changing a checker; it is not in CI either.
- **Not covered:** `.codesight/wiki/` and runbooks (kept current by the CLAUDE.md rule), internal design docs (`docs/*-design.md`, `ARCHITECTURE.md`), and marketing tone.

## Surface registry, sweep engine, ledger and platform matrix (#1728)

- **Engine:** `node scripts/sweep.mjs [dimension ...] [--since <ref>]` is what `/pre-release-sweeps` runs first. For every dimension it runs the tier-1 checker(s) (`check-facts`, the `doc_invocations` cargo test, `check-install-env`, `check-claims` + `check-learn-sync`, `feature-parity`, `i18n-check`, `ui-inventory --check`, `check-ds-config-chain`), then diffs `<ledger sha>..HEAD` (or `--since`) and maps the changed paths onto what the dimension checks: claims anchors (`claims-impact.mjs`), fact sources, registered content by `checked_by`, `en` catalogue keys added and missing per locale, new parity gaps, platform-varying feature code. `--quick` skips the cargo test, `--summary` prints the one `sweeps due: …` line `/release-check` shows, `--list` names every dimension with its lane, checkers and last sweep, `--json` is machine-readable. Exit 1 when a checker or the registry check fails. A lane whose files are absent (`i18n-surfaces` #1724, `store-assets` #1729, `duplication` #1731) prints **NOT BUILT** and never counts as passing; one whose files exist but which `DIMENSIONS` does not wire yet prints **UNWIRED**. `ui-inventory` and `ds-config` are mechanical: the checker is the whole sweep, so they keep no ledger entry.
- **Ledger:** `scripts/sweep-ledger.json`, one `{sha, date, by}` per dimension (#1723 started it for `claims`). `node scripts/sweep.mjs --bump <dims>` records a finished sweep at the `main` commit the branch started from (PRs are squash-merged, so branch commits never reach `main`; `--at` overrides). A dimension with no entry reports "never swept".
- **Registry:** `scripts/surfaces.json` names the axes (platform, skin, store), every public content item (website pages and their scripts, `/learn` topics with their caption tracks and scenes, public and website-linked docs, user-facing READMEs, the installers, store listings and release notes) with `source`, `rendered`, `checked_by` and `policy`, every store, the files under the registration globs that are deliberately internal (each with a reason), and the features whose behaviour varies by platform or skin (with their code `paths`). The `surfaces` dimension checks it both ways: a tracked or untracked-unignored file under `registration.globs` that no entry claims fails, and so does an entry matching no file; `checked_by` must agree with `claims.json` → `audited_docs` and `facts.json` → `asserted_in`; `axes.store` and `stores` must match. Not in CI, like every sweep.
- **Platform matrix:** the `platform-matrix` dimension generates which platform × skin cells (skins apply to the four desktop platforms) have e2e on every PR, e2e in CI but not per PR, e2e by hand only, build/unit only, or nothing, from the workflows (`runs-on`, triggers, `pnpm e2e <scenario>` under the desktop-e2e action, `cargo test -p pollis-tui`, Tauri builds), the native scenarios no workflow runs, the Playwright specs (renderer only, Chromium with Tauri mocked: skin coverage, not platform coverage) and the Maestro flows (by hand: no workflow runs Maestro). It lists the gaps and which `features` they put at risk. Report only; building coverage is separate work. At #1728 the gaps were macOS, Windows and Wayland (no desktop e2e on either skin), the refined skin natively (by hand only), and every mobile platform (Maestro by hand only).
- **Self-test:** `scripts/test-sweep.sh` builds a throwaway git repo from the files the registry and checkers read and proves an unregistered page, a registered page that was deleted, a `checked_by` that disagrees with `claims.json`, and an empty registry each fail; that a missing lane file reports NOT BUILT; that the due list follows `--since` and the ledger; and that `--bump` writes the ledger. Run it after changing `sweep.mjs`; not in CI.
- **Adding a dimension:** add an entry to `DIMENSIONS` in `scripts/sweep.mjs` (`files` that mean it is built, `checks`, a `due` function), a section with its procedure to `.claude/skills/pre-release-sweeps/SKILL.md` under the same id, and its id to the `checked_by` of the content it checks.
